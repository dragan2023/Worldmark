四套主题化方向稿，每套均有移动端 App（390×844 手机框）与桌面 Web（1240px 站点版式）两种可交互预览，内容映射真实种子数据与现有 FastAPI 路由。

挑一套气质，而不是挑一个配色。

四个方案在布局骨架、组件体系、字体系统、交互隐喻上互不相同：霓虹巡礼把地标做成「能量体」，山河印迹把它做成「一枚印」，手帐巡游把它做成「一页手帐」，纯粹志把它做成「一篇特稿」。全部基于同一批真实数据（黑神话：悟空 × 山西古建、边城、子夜、繁花、燕云十六声…），可直接横向对比。

快速选择指南 / WHICH ONE

A 如果你的核心用户因《黑神话：悟空》而来，想运营打卡社区、夜间活动 —— 选 A。
B 如果主打文学/古建/博物馆联名，想把「已核验」卖成信任感、把成就卖成收藏 —— 选 B。
C 如果增长靠内容分享与「出片攻略」，用户以周末轻旅行为主 —— 选 C。
D 如果要一个最快落地、最不容易看腻、方便日后叠加任何运营组件的底座 —— 选 D。
混搭建议（组件可跨方案移植）：以 D 纯粹志 为全站骨架，把 B 的印章集印体系接入成就页，把 C 的票根时间线用于行程详情，把 A 的弹幕条只放在热门地标详情页做氛围 —— 单文件预览里的组件都是独立样式块，搬运成本低。现有 Jinja 模板（app/templates/*）可按此思路逐页替换：home → D、catalog → D+B、itinerary → C/D、contributors → B。
