# 01 — 项目基线与内容模型

## 1. 摘要

- 优先级：P0
- 预计工作量：3–4 人日
- 直接依赖：无；当前项目为空目录
- 阶段目标：建立可本地运行、可迁移、可测试的单体 Web 服务，并锁定三类 IP 共用的数据与权益模型。

## 3. 任务详情

### 3.1 建立最小可运行工程

在根目录新增 `requirements.txt`、`.env.example`、`README.md`、`alembic.ini`、`app/`、`alembic/`、`tests/`。固定如下目录职责：

```text
app/
  main.py                 # 应用工厂、路由注册、静态资源挂载
  core/config.py           # 环境变量与配置校验
  db/session.py            # SQLAlchemy 引擎和会话
  models/                  # ORM 表模型
  schemas/                 # Pydantic 请求/响应模型
  services/                # 筛选、导出、地图、行程等业务服务
  api/                     # JSON API 路由
  web/                     # HTML 页面路由
  templates/               # Jinja 模板
  static/                  # CSS 和最少量浏览器 JS
tests/
  api/ services/ models/   # 与 app 目录对应
```

依赖采用 FastAPI、Uvicorn、SQLAlchemy、Alembic、Psycopg、Jinja2、Pydantic Settings、Passlib/bcrypt、PyJWT、pytest、httpx、openpyxl。地图先使用 Leaflet 的浏览器资源，不安装重型 GIS 服务。搜索能力预留 `SearchProvider` 协议和 `app/integrations/search/` 目录，首选实现名为 `baidu_web_search`；本阶段不实际调用搜索服务，也不在 `.env.example` 填写任何密钥。

### 3.2 定义身份与权益

新增 `app/models/user.py`、`app/models/membership.py`、`app/services/entitlements.py` 与对应迁移。角色使用 `free`、`lite`、`premium` 三个枚举，账号持有当前有效权益，不在控制器中散落字符串判断。

权益矩阵必须由 `EntitlementService` 返回：

| 功能 | free | lite | premium |
| --- | --- | --- | --- |
| 详细地址/简介/交通列表 | 是 | 是 | 是 |
| CSV/XLSX 导出 | 是 | 是 | 是 |
| 静态地图点位 | 否 | 是 | 是 |
| 静态推荐线路 | 否 | 是 | 是 |
| 个性化行程生成与保存 | 否 | 否 | 是 |

未登录访问按 `free` 处理；首期由管理员在后台设置和调整 `membership`，所有页面与 API 都只通过 `EntitlementService` 判断权益。

### 3.3 定义统一内容模型和地理层级

新增 `app/models/ip_work.py`、`landmark.py`、`location.py`、`source.py`、`route.py`。第一版至少包含以下核心字段：

```text
ip_works(id, title, aliases, ip_type, creator, release_year, synopsis, status)
locations(id, country_code, country_name, province_name, city_name, district_name, normalized_address, latitude, longitude)
landmarks(id, ip_work_id, location_id, name, description, transit_text, landmark_kind, verification_status, published_at)
sources(id, url, publisher, title, accessed_at, license_note, source_type)
landmark_sources(landmark_id, source_id, claim_scope, reviewed_by, reviewed_at)
routes(id, ip_work_id, city_name, title, summary, duration_text, status)
route_stops(id, route_id, landmark_id, stop_order, stay_minutes, note)
search_runs(id, provider, query_template, query_text, requested_at, provider_request_id, result_count, status, error_summary)
```

`ip_type` 仅允许 `literature`、`game`、`screen`；`verification_status` 至少区分 `candidate`、`verified`、`rejected`；公开查询只返回 `verified` 且已发布的地标。国家采用 ISO 3166-1 alpha-2 代码，省、市保留名称字段；不要把中国省市行政区编码硬编码到业务逻辑。

### 3.4 建立基础页面、接口和测试基线

实现 `/health/live`、`/` 和 `/api/v1/meta/ip-types`；首页应显示三个模块入口及各权益的准确文案。为健康检查、配置缺失、枚举约束、迁移升级、未登录免费权益各写至少一条测试。

## 5. 禁止修改与风险红线

1. 不接入订单、收款、支付回调、退款、第三方登录、地图密钥、大模型调用或网页抓取；搜索能力只建立可替换的 API 适配边界。
2. 不为了三类内容分别复制三组表、路由或页面；差异通过 `ip_type` 和内容字段表达。
3. 不将坐标、地址、作品名称或来源直接写在模板中作为长期数据。
4. 不在没有迁移的情况下创建或修改业务表。

## 6. 验收标准

- [ ] 新开发者可仅依靠 `README.md`、`.env.example`、项目内 `.venv` 和 PostgreSQL 启动首页与健康检查。
- [ ] Alembic 从空数据库执行升级后，核心表、唯一约束和枚举约束均可创建。
- [ ] 首页能看见文学、游戏、影视三个入口和三档权益说明。
- [ ] 测试覆盖免费/轻量/高级三个角色的权益矩阵，且全部通过。
- [ ] 所有密钥仅来自环境变量，`.env.example` 不含真实值。
