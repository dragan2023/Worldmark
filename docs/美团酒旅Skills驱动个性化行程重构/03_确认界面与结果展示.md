# 03 — 确认界面与结果展示

## 1. 摘要

优先级：中。预计工作量：中。直接依赖：02。阶段目标：让用户看到完整的官方旅行建议、来源、查询状态和可确认项，并能清楚区分已确认计划与仅供参考的动态信息。

## 2. 前置阅读

1. `app/templates/itineraries/form.html`
2. `app/templates/itineraries/detail.html`
3. `app/static/js/itinerary-form.js`
4. `app/static/css/itinerary.css`
5. `app/api/itineraries.py`

## 3. 任务详情

2.1 提交表单后展示“正在连接美团酒旅规划，通常需要 1–2 分钟”的明确加载状态、可恢复错误和超时说明。

2.2 在确认页完整展示官方文本结果；对链接进行安全协议校验后保留原始跳转链接。

2.3 可确认的交通、住宿、景点和餐饮项必须显示来源、查询时点和原始价格文本；没有明确金额或无法归一的项目只作为参考，不可自动写入预算。

2.4 在详情页和 API 响应中显示生成来源（美团官方 Skill / 本地降级）与生成告知，不泄露原始 Token 或诊断细节。

## 4. 禁止修改与风险红线

1. 不通过前端直接调用美团服务。
2. 不隐藏降级状态，也不把参考价显示为已确认价。
3. 不移除用户现有的自定义交通、住宿和补充项输入能力。

## 5. 验收标准

- [ ] 美团规划中的原始重要信息与安全链接可供用户查看。
- [ ] 确认步骤只把用户选择的内容写入最终计划和预算。
- [ ] 美团异常和本地降级在界面中可辨识。
