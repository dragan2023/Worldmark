# 美团酒旅 Skills 驱动个性化行程重构

## 1. 使用方法与总体原则

本计划将美团酒旅官方 Skill 作为旅行方案与供给信息的主要来源；本项目仍负责 IP 地标约束、用户确认、路线优化、保存、展示和导出。实施时按阶段顺序执行，每完成一个阶段即运行该阶段的验收命令。

1.1 官方 Skill 源文件归档到 `docs/第三方Skills/美团酒旅/official-skill/`，仅作为接入规范和版本留档；运行时通过官方 `@meituan-travel/ht-ai` CLI 调用，不复制或修改官方脚本。

1.2 服务端只从 `MEITUAN_HT_TOKEN` 读取官方 Token；为兼容已有本地配置，可临时回退读取旧变量 `MEITUAN_TRAVEL_TOKEN`，但不会把任一 Token 写入数据库、响应、日志或浏览器代码。

1.3 美团返回内容是不可信的外部输入。保存前必须完成字段白名单、链接校验、日期/城市/预算约束和已发布 IP 地标约束校验；价格、余票、营业和预约状态都只作为查询时参考。

1.4 不以正则猜测 Markdown 或私有 `<ka>` 标签作为主数据协议。优先请求官方 raw JSON；同时保留格式化文本供完整展示和诊断。

## 2. 全局红线与范围边界

1. 不调用未在官方 Skill 中声明的 REST 接口，也不将 Token 暴露给前端。
2. 不把美团推荐的非 IP 地点伪装成本地 `Landmark`，它们只保存为当日补充项或已确认的旅行要素。
3. 不删除现有 IP 地标候选校验、用户确认步骤、路线优化、地图和 HTML/DOCX/XLSX 导出能力。
4. 不承诺或自动下单酒店、交通、门票；页面只提供原始官方链接或用户明确确认后的方案。
5. 测试必须离线可重复；真实美团调用只在显式本地验收中执行。

## 3. 推荐执行顺序

| 编号 | 计划名称 | 核心目标 | 主要范围 | 预计工作量 |
| --- | --- | --- | --- | --- |
| 01 | 官方 Skill 归档与运行时适配 | 以官方 `ht-ai` CLI 替换旧 `mttravel` 包装器 | `docs/第三方Skills/`、`app/integrations/`、配置与单元测试 | 中 |
| 02 | 美团方案归一与行程主链 | 用完整旅行请求驱动候选预览和日程生成 | `app/services/`、`app/schemas/`、行程服务测试 | 大 |
| 03 | 确认界面与结果展示 | 展示完整官方结果、可确认要素与降级状态 | `app/api/`、模板、前端脚本、样式 | 中 |
| 04 | 回归验证与运行文档 | 覆盖离线回归和真实连通性验收 | `tests/`、`docs/运行手册.md`、`docs/故障处理手册.md` | 中 |

## 4. 依赖关系

```text
01 官方适配
   ↓
02 方案归一与主链 ───→ 03 界面与展示
   ↓                         ↓
   └──────────────→ 04 回归验证与运行文档
```

4.1 阶段 01 必须先完成；阶段 02 依赖阶段 01 的稳定 raw JSON 契约。

4.2 阶段 03 可在阶段 02 的归一对象确定后开始；阶段 04 在其他阶段完成后统一执行。

## 5. 每次开发的统一要求

1. 使用项目 `.venv\\Scripts\\python.exe` 运行迁移、测试和服务。
2. 所有外部 CLI 调用设置超时并把错误归类为鉴权、超时、服务错误或解析错误。
3. 单元测试中替换官方 CLI 进程调用；不得依赖真实 Token、网络或当前用户目录。
4. 保存前记录实际生成器版本和数据来源，供页面说明和故障诊断使用。

## 6. 运行与验证前置条件

1. `MEITUAN_HT_TOKEN` 配置在本机 `.env` 或部署环境变量中；旧 `MEITUAN_TRAVEL_TOKEN` 仅为过渡兼容。
2. Node.js 18+ 和 `npx` 可用，首次调用可由 `npx` 获取官方 `@meituan-travel/ht-ai` 包。
3. 本地数据库已升级至当前 Alembic 版本，测试使用临时 SQLite 数据库。
