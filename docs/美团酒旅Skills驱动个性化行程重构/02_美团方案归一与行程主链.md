# 02 — 美团方案归一与行程主链

## 1. 摘要

优先级：高。预计工作量：大。直接依赖：01。阶段目标：以一条完整自然语言行程请求驱动美团方案查询，将可靠字段归一为项目现有的预览、确认和持久化结构。

## 3. 任务详情

2.1 建立 `MeituanTravelPlan` 归一对象：原始官方结果、用户可读完整内容、酒店/交通/景点/餐饮候选、链接、可见价格文本、解析警告和查询状态。

2.2 根据出发城市、目的城市、日期、人数、预算、同行方式、交通偏好、兴趣、用户补充要求和已选 IP 地标构建一个完整 query。已选 IP 地标必须以不可替代的必去条件写入 query。

2.3 将 `choice-preview` 改为只触发一次主规划调用，并以归一对象输出给前端；必要时对单项做按需补查，而非预先多轮调用。

2.4 非确认创建调用使用美团规划结果作为主输入；本地只安排已发布 IP 地标的顺序、时间与地理优化。官方结果不能满足结构化保存要求时，保留其展示结果并明确降级到本地确定性排程。

2.5 保持 `confirmed_plan` 的本地确定性生成器：它只消费用户确认的交通、住宿、景点、餐饮及 IP 地标，避免将未确认的实时供给写入最终计划。

2.6 删除主路径中依赖 `_HOTEL`、`_TRANSPORT`、Markdown 链接正则和猜测型价格匹配的代码；兼容旧记录的展示读取不受影响。

## 4. 禁止修改与风险红线

1. 仍必须校验 `must_visit_landmark_ids` 属于已发布的国内 IP 地标候选集。
2. 不让外部返回覆盖用户日期、必去地标、排除地标或确认过的价格。
3. 不把实时库存、票价、营业或预约状态描述为承诺。

## 5. 验收标准

- [ ] 美团成功结果会成为预览和非确认生成的主要旅行信息来源。
- [ ] 必去 IP 地标、排除条件、日期和预算限制在归一后仍然有效。
- [ ] 格式变化、空结果、服务超时或鉴权失败都得到可读状态，并有安全的本地降级。
- [ ] 行程、确认和旧导出相关服务测试全部通过。
