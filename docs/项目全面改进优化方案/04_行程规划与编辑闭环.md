## 2. 任务详情

### 2.1 基础规划与外部增强明确分工

保留现有确定性生成器，作为“基础行程”正式能力；经授权的 level1/admin 无外部密钥仍可按真实已发布地标生成。页面默认调用统一规划入口，由用户明确选择是否开启外部增强，不把“美团未配置”当作所有规划不可用。

整理 create/finalize/choice-preview 职责：基础生成一条明确路径，增强流程使用同一校验与持久化逻辑。finalize 如仍有外部调用方，保持兼容但转调有效实现；无调用且非契约的旧确认流程应连同无效前端、字段和测试收敛，不按函数名直接删除。

响应区分基础结果、增强完整、增强部分失败；例如 generation_mode、warnings、缺失费用数量。不得将模型推断、上游推荐或未知价格写成“用户已确认”。真实凭据调用仍需用户授权，本阶段用替身覆盖完整/缺配置/超时/格式错误。

### 2.2 限制长请求的成本和失败影响

服务端给日期跨度、每天小时、必去点数量、补充项目数量设置与当前产品容量匹配的上限，前后端一致；必须保留已有八日行程测试有效行为。以离线样本量测选定上限并记入文档，不用无限数组或日期范围放大调用量。

设置整体规划耗时预算、各 provider 超时和总调用上限；重试仅用于可重试且幂等的请求。页面提供真实阶段或诚实的等待状态，禁止假的百分比和自动无限重试。请求未结束前防重复提交；重试时使用请求标识去重，避免重复费用和重复行程。

当前先保持有界同步流程。不仅为 1–2 分钟文案引入 Celery/Redis；若实测仍超部署超时且确需离页继续，再另行设计持久任务和独立 worker，不能用进程内 BackgroundTasks 假装可恢复队列。

### 2.3 历史行程引用与编辑一致性

软删或撤回地标后，已有行程仍可显示“地点已不可用”占位，保留用户备注，不返回未公开内容；新增规划不得再选该点。梳理 API、模板、地图和所有导出对 stop.landmark 的假设，禁止全局 include_deleted 来解决显示问题。

编辑按现有 day/stop 更新或完整保留未修改的 supplemental_items、travel_context。对受修改影响的时序、预算与来源做统一重算或标记待确认；不能仅清空上下文或留下过时费用。

利用已有 version 字段，增加 expected_version 输入并进行数据库条件更新/事务检查；冲突返回 409，用户可刷新比较，不能悄悄覆盖。验证重复站点、必去点遗漏、非公开引用及不合理时间，保留必要例外的明确语义。

### 2.4 坐标、动线和价格语义

数据库与 OSM 展示统一 WGS84；高德请求边界转换为其要求的坐标系，高德酒店结果转回 WGS84 后参与本地距离比较。复用 geocoding.py 已有转换，避免第二套算法；用替身断言边界参数，不需真实高德调用。

重排行程不能忽略站间移动时间或将跨日时间显示成 26:00；区分步行参考与用户交通偏好，缺路线结果明确显示估算。保留城市间移动及住宿锚点，不将跨城行程按步行组织。

未知价格用 null/待确认，不以 0 代表免费。明确人数、房间/晚数、单次票价口径，汇总表与预算说明一致。

### 2.5 输出与前端编辑闭环

新增适配现有 PATCH 的编辑 UI（可在 itineraries/detail.html 与新建 itinerary-editor.js 中实现），支持名称、备注、站点调整；非必要不引入拖拽库。HTML/DOCX/XLSX 使用同一有效行程数据；均保留价格说明、失效地点提示和缺失项目。

用户/上游文本进入 XLSX 必须按文本写入，系统生成的 SUM 公式仍保留；CSV 如未来恢复另处理危险前缀。修复不应只针对一个示例字符串。

## 3. 禁止事项与兼容约束

不编造坐标、营业时间、班次、票价或来源；不擅自调用系统/用户密钥；不取消现有角色限制；不自动预订。已有行程不因软删整条失效；用户备注和已确认安排不能因编辑丢失。

## 4. 验收标准

- [ ] 无密钥基础行程可从页面完成，API/页面/文档描述一致。
- [ ] 增强失败、超时、格式错误有准确提示且不重复入库；调用次数受控。
- [ ] 历史地标撤回或软删后，详情、地图、三种导出无 500 且不暴露未公开内容。
- [ ] 编辑后补充安排与用户备注保留，预算/时间同步；过时版本提交为 409。
- [ ] 坐标边界替身测试通过，国内已知坐标转换与地图位置一致。
- [ ] 八日、多城市、人数/住宿、缺价格、时序冲突等真实边界通过。
- [ ] XLSX 外部文本不变公式，合法汇总公式保留；三种导出内容一致。
- [ ] 替代入口的调用方和废弃字段/分支清理完成，无静默回退掩盖缺陷。
