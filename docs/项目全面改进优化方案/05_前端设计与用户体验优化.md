# 05 — 前端设计与用户体验优化

## 1. 摘要

优先级 P1/P2；预计 4–6 日；依赖 02 的权限、03 的媒体及 04 的行程接口；视觉和公共布局可提前准备。目标：让用户顺利完成发现、规划和贡献，保留“山河印迹”品牌。对应 B06 和调研体验问题。

### 1.1 前置阅读

`design/README.md`、`design/web-b-guochao.html`、`design/scheme-b-guochao.html`；`app/templates/_header.html`、`_footer.html`、`home.html`、`search.html`、`catalog/index.html`、`catalog/detail.html`、`catalog/map.html`、`itineraries/form.html`、`agent_intake.html`；`app/static/css/site.css`、`catalog.css`、`itinerary.css`、`app/static/js/auth.js`、`landmark-map.js`、`itinerary-form.js`、`app/web/search.py`、`app/api/contributor.py`。模板短路径均相对 app/templates。

## 2. 任务详情

### 2.1 收敛设计语言与页面骨架

从 site.css 现有色彩变量扩展字号、间距、控件高度、边框、状态色，不再生成另一套无关风格。标题用宋体风格，长正文/表单用系统无衬线；默认正文 15–16px、舒适行距，避免所有文字加大字间距。弱化文字与纸色对比不够时加深，不能为装饰牺牲可读性。

在 `app/templates/base.html` 建立公共 head/header/footer 和样式脚本 block，迁移本次触达模板后删除重复骨架；未迁移模板仍须可运行，不强制一次重写所有管理页面。外部字体失败时系统字体保持可读，不让第三方字体成为渲染必要条件。

桌面保持约 1160px 内容宽度；首页压缩装饰横幅，把搜索和主要分类放进首屏。导航用用户语言“发现地标 / 我的行程 / 参与共创”，分类仍保留文学、游戏、影视；角色工具收进账户区域。补当前页 aria-current。

### 2.2 发现到详情的路径

首页“查看全部”改为真实全分类目录/搜索入口，若不新增全分类页则改为明确“查看文学地标”，不能继续误标。全局搜索增加 page/page_size 参数及翻页，保留 q；空结果有清除条件和分类入口，超页能返回有效页面。

目录列表与地图互切保留筛选；卡片保留作品、地标、地区、更新时间、必要摘要，避免每张卡都放满长地址。图片预留比例并懒加载，失效图有可理解占位。

详情主要布局：
```text
作品/分类面包屑 → 地标名、地区、可信来源
相册与简介 → 地址、交通参考、更新时间
主要动作：加入行程；次要动作：地图查看
可编辑者：编辑内容与相册；其他人不展示伪可用入口
```
加入行程传 landmark_id 到新建表单并验证，不能信任 URL 中的展示文案。匿名先登录，level2 显示现有贡献升级条件，已满足权限者直接保留选择。

### 2.3 修复地图与补足可访问交互

保存 groupEl 引用，修复搜索异常；选定查询语义为“过滤列表与可见标记”，同步更新数量和空态。重置同时清查询并定位全部，避免只改变缩放。侧栏地标用 button/link，支持键盘聚焦与激活。

移动端地图/列表用明确切换或上下布局，减少滚轮与页面滚动冲突。单点、零点、瓦片失败和 API 失败均有可读反馈，不能只修改 aria-label。保留正确服务署名，不下载或预抓取地图瓦片。

### 2.4 表单、登录和生成体验

行程表单按“地点与日期→出发/人数/预算→可选偏好”分组，折叠低频选项；不是强制多页面向导。选择器支持分页、已选标签和移除，跨搜索保留选择，回车搜索。请求去重或取消旧请求，防止较慢结果覆盖新查询。

抽取小型共享错误解析工具 `app/static/js/api-errors.js`，支持字符串 detail、对象 code、Pydantic 错误数组和网络错误；迁移实际使用者，不建立大型前端框架。错误关联到字段并将焦点移到摘要；进度 aria-live，失败后保留输入并允许明确重试。

auth.js 支持合法站内 next，防开放重定向；双击提交不重复请求，网络失败不显示登录成功。个人密钥页说明“哪个功能需要哪个服务”，从缺配置提示回到原任务。浏览器存储仅保存非敏感草稿字段，不存密钥、密码、token 或完整私人备注。

### 2.5 共创闭环与真实状态

在 app/api/contributor.py 增加当前用户贡献分页查询（拟定 GET /api/v1/me/contributions），以 contributor_user_id 过滤；新增 `app/web/contributions.py`、`app/templates/contributions/index.html` 并在 main.py 注册。展示候选/已核验未发布/已发布/被拒绝及更新时间、可见审核反馈和合法编辑入口。被软删条目仅显示必要状态，不能穿透公开过滤读取其他人的记录。

贡献成功跳往自己的记录/候选编辑入口；明确“修改后将暂时下架并重审”，避免用户误认为保存即公开。贡献升级基于实际发布，不能虚构进度、积分或勋章。复用现有贡献/审核模型，不新增社交系统。

## 3. 禁止事项与兼容约束

不把 design 原型中的演示数据、AR、打卡数当作真实能力；不未经依据恢复已移除的目录导出；不靠前端隐藏实现鉴权；不阻止密码管理器粘贴；不无限增加动画和字体。未授权正式内容不进入截图。

## 4. 验收标准

- [ ] 360、390、768、1280、1440px 下主要流程无页面级横向溢出，表格独立滚动。
- [ ] 地图多分组搜索、清空和重置无控制台异常，列表与标记同步。
- [ ] 搜索超过 30 条、选择器超过 50 条可访问后续结果且保留选择。
- [ ] “详情→登录/权限说明→加入行程→生成→编辑→导出”完整走通。
- [ ] “贡献→个人记录→重审反馈→编辑”完整走通，无跨用户读取。
- [ ] 正常文本对比度至少 4.5:1，大字至少 3:1；主要触控目标采用至少 44×44 CSS px 设计目标。
- [ ] Tab/Enter/Escape 可操作导航、弹窗和地图侧栏，焦点可见且不被遮挡。
- [ ] 无密钥、空结果、网络失败、上游失败和超时有明确状态与下一步。
- [ ] 每类模板骨架/错误处理迁移后，重复旧代码同步删除；桌面与手机截图留证。
