# 01 — 运行基础与数据库迁移

## 1. 摘要

优先级 P0/P1；预计 2–3 日；直接依赖：无。目标：安装声明完整，空库和历史库均能通过统一迁移进入可运行状态，生产配置拒绝已知不安全默认值。对应 B01、B12、R02。

### 1.1 前置阅读

`requirements.txt`、`.env.example`、`README.md`、`alembic/env.py`、`alembic/versions/0001_initial_schema.py` 至 `0007_itinerary_day_travel_context.py`、`scripts/migrate_user_roles.py`、`app/models/user.py`、`app/models/user_api_key.py`、`app/models/landmark.py`、`app/core/config.py`、`app/core/secret_box.py`、`tests/conftest.py`、`scripts/verify_mvp.ps1`。

## 2. 任务详情

### 2.1 补齐直接依赖与可复现安装

明确声明 cryptography；核查现有 import 与依赖用途。密码现由标准库 PBKDF2 实现，不因 README 写了 bcrypt 就保留无调用的 passlib[bcrypt]。删除前全局检查脚本、测试和动态加载。记录支持的 Python 与经过验证的依赖组合；不要照抄当前虚拟环境全部包。保持现有 requirements 机制，必要时增加验证过的约束清单，不另建配置框架。

在项目内新建临时验证虚拟环境安装清单、导入 app.main、执行最小账号与密钥测试。系统 Python 仅可用于创建虚拟环境，不向系统安装包。

### 2.2 用增量 Alembic 迁移补齐模型

新增 `alembic/versions/0008_user_schema_alignment.py`（实施前先检查编号是否已占用），覆盖缺列、缺表、索引、唯一约束、username 非空约束及回填。不要改写已经应用的 0001–0007。

必须支持：
1. 从空库升级；从 0007 库升级。
2. 部分执行过旧迁移脚本的库：先检查列与约束，再补缺，不重复添加。
3. 重复邮箱前缀、三个以上同名前缀、空值、超长或非法用户名。回填使用确定性唯一用户名，例如符合格式的 user_<id>，不以相同“-2”处理全部冲突。
4. 按原有管理员标记保留实际管理员权限；不自动创建新的管理员。
5. SQLite 与 PostgreSQL 的 DDL 差异；避免 DATETIME/instr 等方言 SQL 直接流入 PostgreSQL。

新增 `tests/migrations/test_schema_upgrade.py`，由 Alembic 创建库后验证模型查询和注册/登录/个人密钥流程，不用 create_all 替代被测迁移。历史数据使用合成快照；迁移前后核对行数和引用。

### 2.3 收敛旧迁移入口

将 scripts/migrate_user_roles.py 的有效迁移职责迁入 Alembic；核查 README、启动器、脚本调用方后删除被完整替代的脚本。历史 Alembic 文件保留。旧库差异不明时先输出只读差异报告，不能通过删库或 create_all 掩盖。

### 2.4 配置及启动检查

在 config.py 验证 production 不得使用空值、已知示例或开发默认 APP_SECRET_KEY，要求足够随机的密钥；错误只说配置项名，不能回显值。禁止程序自动旋转密钥，避免已加密用户密钥失效。

完善 README 虚拟环境创建、迁移、启动和测试命令。当前 BAT 内容为 ASCII；若修改启动流程，保持 ASCII BAT，必要时使用同目录 ASCII 名 start.ps1 与 $PSScriptRoot。只在隔离 DATABASE_URL 下运行启动验收，不能由现有 BAT 自动升级正式库。

## 3. 禁止事项与风险

不删除历史数据、密钥或迁移；不无条件 stamp head；不把测试默认数据库改为正式库；不把“pip check 通过”等同于干净安装通过。正式数据迁移、密钥轮换和真实 PostgreSQL 环境操作若未授权，只准备脚本和演练报告。

## 4. 验收标准

- [ ] 新虚拟环境仅靠清单可导入应用并完成最小流程。
- [ ] 空库、0007 库、部分手动升级库均迁移成功，模型缺列/缺表为零。
- [ ] 唯一用户名、历史管理员、用户密钥归属与地标软删字段迁移正确。
- [ ] 隔离 PostgreSQL 执行同样迁移与关键事务；无环境时如实列为未完成验收。
- [ ] production 的默认/空密钥启动失败且不泄露密钥。
- [ ] 如修改 BAT，非 ASCII 字节为零，cmd.exe /d /c 启动隔离服务且健康接口通过。
- [ ] 被替代迁移脚本及其文档入口已收敛，历史迁移和用户资料保留。
