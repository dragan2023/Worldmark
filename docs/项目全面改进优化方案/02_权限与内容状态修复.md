# 02 — 权限与内容状态修复

## 1. 摘要

优先级 P0/P1；预计 3–4 日；直接依赖 01。目标：同一用户在页面/API 的能力一致，普通用户不调用系统密钥，单个条目的编辑审核只影响应影响的内容。对应 B02–B04、B11、R01、R08。

### 1.1 前置阅读

`app/core/auth.py`、`app/services/permissions.py`、`app/services/entitlements.py`、`app/services/key_resolution.py`、`app/api/itineraries.py`、`app/web/itineraries.py`、`app/api/admin.py`、`app/api/admin_users.py`、`app/api/contributor.py`、`app/api/album.py`、`app/services/review.py`、`app/services/landmark_catalog.py`、`app/services/data_quality.py`、`tests/api/test_permissions.py`、`tests/api/test_contributor_edits.py`。

## 2. 任务详情

### 2.1 统一权限事实来源

行程页面与所有读写/导出 API 使用相同 level1 权限守卫；匿名页面跳登录并携带经过校验的站内 next，API 返回 401；level2 得到明确能力说明和贡献入口，API 返回 403。不能创建共享匿名账号来规避要求。

检查 resolve_user_id 的全部调用；迁移行程调用为已认证 member.user_id 后，删除无使用者的共享匿名逻辑及过时注释，保留历史账号数据。公开地图和路线保持公开，不因整理权限收紧公开浏览。

核查 is_admin 与 role 双重判断。将既有管理员兼容规则收敛为一致的有效角色解析，确保 /me 与服务端授权一致；是否删除旧数据库字段取决于真实迁移证据，不猜测。旧 X-Admin-Token 有脚本调用方时不得盲删，保留条件和移除条件写清楚。

### 2.2 统一用户密钥注入

修复 /choice-preview 为与 create/finalize 相同的用户 Settings 注入。扫描 agent、album、预览、重处理与验证密钥等入口。普通用户无自配密钥时不得回落系统密钥；匿名不得接入付费操作；管理员允许已有规则下的系统回落。

用 MockTransport/服务替身捕获 provider 使用来源，不记录原始值。测试覆盖“用户自配、用户缺失、管理员回落、解密失败、已封禁”并确保所有相关入口行为一致。将缺配置与上游失败区分为稳定错误 code，返回可用配置路径。

### 2.3 建立准确的公开条件和状态转换

公开地标条件统一为：
```text
未软删 AND verification_status=verified
AND published_at 非空 AND 所属作品处于 published
```
将目录、搜索、筛选选项、地图、路线和规划候选统一到相同规则。避免搜索另写一套漏条件的查询。

贡献者编辑与相册重审仅撤回目标地标，不无条件将作品置 draft。单条 unpublish 同理。已发布条目重新判 rejected 时同时撤回 published_at；恢复软删不越过审核要求。作品级下架如已有真实业务需求仍作为单独操作，不与地标下架混用。

在 review.py 等现有服务内集中转换逻辑，迁移 admin/contributor/album 调用后删除重复写状态代码。增加“同作品两个已发布地标”的回归用例，覆盖改文案、改相册、拒绝、下架、软删和恢复。

### 2.4 输入、审计及账号边界

名称/简介先 trim 再校验非空，管理员和贡献者一致；明确 None 与清空可选字段的区别。角色字段使用明确枚举，未知输入不能静默变 level2。注册并发的唯一约束冲突转为 409 并回滚，避免 500。

发布复用 data_quality 的有效检查，统一最小来源与内容要求。审核者身份取服务器认证信息；对内容编辑、下架、恢复、角色与封禁操作保留必要的操作者和时间，避免日志存储密码、密钥或完整私人行程。会员到期时间归一化后比较，补 SQLite 与 PostgreSQL 边界测试。

## 3. 禁止事项与兼容约束

不开放行程给匿名或 level2；不只隐藏前端按钮代替后端鉴权；不删除历史会员、贡献归属和审计记录；不一并下架同作品其他有效地标。不能把审核来源 URL 自动访问验证变成每次提交的不可控网络调用。

## 4. 验收标准

- [ ] 匿名、level2、level1、admin、banned 的页面/API 权限矩阵一致，无 B02 的 500。
- [ ] 用户 A 不能访问或改写用户 B 的行程、密钥、非本人贡献条目。
- [ ] /choice-preview 等入口均不使用普通用户未配置的系统密钥。
- [ ] 拒绝/撤回内容从公开详情、列表、搜索、地图、路线及新规划候选消失。
- [ ] 变更一个地标不影响同作品另一个已发布地标。
- [ ] 空白字段、非法角色、注册冲突得到稳定错误，事务无部分写入。
- [ ] /me 权限与服务端一致；身份和状态判断的重复实现已清理。
