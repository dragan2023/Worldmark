# 上线前数据检查清单

## 1. 使用方式

每次准备将地标或推荐路线公开前，由内容审核人员逐项检查。任一阻断项不通过时，保持草稿或撤回发布，不以页面可访问替代数据审核。

## 2. 地标记录检查

- [ ] 作品名称、作品类型（文学 / 游戏 / 影视）和地标关联有可访问来源支撑。
- [ ] 地标名称、详细地址、国家、省/州、城市的层级一致。
- [ ] 至少有一条来源记录、访问日期和审核记录。
- [ ] 原创简介不是大段复制的受版权保护内容，且不把推测写成事实。
- [ ] 如填写后台交通文字，必须有来源且不承诺实时班次、票价、营业、预约或安全状态；免费页面和导出不展示该字段。
- [ ] 若为会员地图展示，坐标与详细地址相符；坐标缺失时不发布地图点位。
- [ ] 信息变更、来源失效或版权存疑时，先撤回发布，再补充审核证据。

## 3. 推荐路线检查

- [ ] 每一站均为已发布且已核验的地标。
- [ ] 站点顺序、建议停留时间和地址一致。
- [ ] 页面与导出文件包含必要来源和出行前确认提示。
- [ ] 没有把高德、美团或搜索结果写成实时库存、价格、营业或预约承诺。

## 4. 发布门槛

在干净验证环境运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\verify_mvp.ps1
```

脚本会使用临时 SQLite 数据库执行迁移、已发布数据质量检查和完整测试；任何一步失败均不得发布。

## 5. 共创条目与名单检查

- [ ] `data/contributions/entries/` 下已无待导入的条目文件（已全部移入 `archive/YYYY-MM-DD/`，仅保留目录占位文件）。
- [ ] 归档目录含对应日期的 `manifest.json`，且每条导入记录都能在种子数据中找到对应地标（`ip_type + work_title + landmark_name`）。
- [ ] 种子数据 `data/seed/landmarks_verified.csv` 无重复行（按 `ip_type + work_title + landmark_name + normalized_address` 判重）。
- [ ] `data/contributions/contributors.json` 的共创者用户名、`github_url`、`first_merged_at`、`merged_entries` 与归档记录一致，无缺失或手工覆盖。
- [ ] 数据库 `landmark_contributions` 表为每个有 GitHub 用户名的归档记录写入署名（`contributor_name` 非空且不重复）。
- [ ] 执行发布脚本（`python scripts/import_contribution_entries.py --dry-run`）输出无待导入条目、无越界文件。
- [ ] 发布工作流 `.github/workflows/publish-contributions.yml` 可手动触发，且回写只涉及 `data/seed/`、`contributors.json` 与 `archive/`。
- [ ] 前端 `/contributors` 页面可访问并实时显示名单；`GET /api/v1/contributors` 返回与 `contributors.json` 一致的 JSON。
- [ ] 已发布的共创地标可通过页面/接口按作品与地标名查询到，且详情页展示对应共创者署名。
