# 共创贡献规范

## 1. 提交方式

访问 `/contribute` 填写共创者署名、作品、地标、详细地址、三段式地标简介和至少一个可访问来源。提交后系统创建候选条目，状态为 `candidate`；候选内容不会出现在公开目录、导出或地图中。

## 2. 署名与身份

每次提交都会写入 `landmark_contributions`：

1. `contributor_name`：必填的公开署名，审核发布后显示在地标详情页。
2. `contributor_user_id`：可为空。提交者携带有效登录令牌或站内登录 Cookie 时自动记录；后续开放共创角色、修改权限和个人贡献页时以该字段作为身份关联。
3. `landmark_id`：指向本次提交产生的候选地标，因此可准确追踪“谁提交了哪一条”。

未登录提交的署名属于自我声明，不等同于已验证身份；审核人员可以通过来源与后续账号绑定进行核验。

## 3. 审核与公开

管理员通过既有审核接口核验候选条目，只有变为 `verified` 后才能单独发布。发布后的详情页显示共创者姓名；被拒或仍在候选状态的贡献记录仅由管理员在 `GET /api/v1/admin/contributions` 查看。

## 4. 数据边界

不要填写联系方式、住址、证件信息或其他不必要个人信息。公开署名请使用愿意被显示的名字或昵称。每条简介必须使用“在作品中的重要地位”“主要出现的情节”“现实地标介绍”三段式原创内容，并提供可访问来源链接。

## 5. PR 共创方式

除网页表单外，共创者可以使用主流 AI 智能体（Codex、Claude Code、WorkBuddy、Qoder 等）按提示词包自动生成条目并以 PR 提交。

### 5.1 两种提交路径的适用场景

1. **网页提交（`/contribute`）**：单条、快速、无需代码；署名手动填写。
2. **Harness PR 工作流**：需要联网核实与批量、可复用、可追溯的共创；条目以独立 CSV 文件提交，GitHub 审核机器人自动校验，维护者合入后自动归档。

### 5.2 流程与入口

1. 完整流程、工具启动方式与常见问题见 `docs/共创提示词包/00_使用说明.md`。
2. 可直接整段复制的提示词见 `docs/共创提示词包/01_共创条目添加提示词.md`。
3. 条目文件格式与校验规则见 `data/contributions/entries/README.md` 与 `scripts/validate_contribution_entry.py`。

### 5.3 署名规则（GitHub 用户名）

PR 共创条目不写入署名；合并导入时自动使用 PR 作者的 GitHub 用户名作为署名，并累计到共创者名单。

### 5.4 共创者名单页面

项目前端提供 `/contributors` 独立页面（及 `GET /api/v1/contributors` 接口），实时读取 `data/contributions/contributors.json`，展示共创者的 GitHub 用户名、GitHub 主页、加入时间与累计合并条目数。名单文件仅由发布流水线维护，共创 PR 不得修改。

### 5.5 与既有审核流程的关系

PR 条目经机器人确定性校验与维护者人工合入后，随既有 `seed_initial_landmarks` 发布流程进入候选 → 审核 → 发布链路；机器人只备数据，不直连生产数据库。
