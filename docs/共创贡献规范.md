# 共创贡献规范

## 1. 提交方式

共创通过应用内 **AI 一键入库** 完成，不经过 GitHub 仓库、不需要配置开发环境：

1. 注册 / 登录（注册即为二级用户，已具备一键入库权限）。
2. 打开 `/intake`「一键入库」页，用一句自然语言描述「作品 + 地标」，例如「情书 小樽运河」。
3. AI Agent 依次完成：解析作品与地标 → 联网核实现实资料 → 生成三段式原创简介与结构化字段 → 地理编码补全坐标 → 以**候选（candidate）状态入库**。

对应接口为 `POST /api/v1/agent/landmarks/intake`，请求体 `{"input": "作品名 地标名"}`，需要登录会员身份。仓库不再接收共创 Pull Request，也没有 PR 审核机器人。

## 2. 署名与身份

每次入库都会写入 `landmark_contributions` 署名记录，与提交账号直接绑定：

1. `contributor_user_id`：提交者的应用内账号，条目发布后据此在详情页展示署名；
2. `contributor_name`：展示名（用户名，缺失时回落到邮箱前缀）；
3. `landmark_id`：指向本次提交的候选地标，可准确追踪「谁提交了哪一条」。

署名无需手工填写，入库时自动确定。

## 3. 审核与公开

候选条目不会出现在公开目录、导出或地图中。管理员在 `/admin` 复核，只有变为 `verified` 并发布后才对公众可见，详情页显示提交者署名；提交者账号在条目发布后自动升为一级用户（只升不降，幂等）。

## 4. 数据边界

不要填写联系方式、住址、证件信息或其他不必要个人信息。公开署名为你的应用内用户名。每条简介必须使用「在作品中的重要地位」「主要出现的情节」「现实地标介绍」三段式原创内容，并提供可访问来源链接；系统不会编造来源与坐标，缺少联网核实或地理编码能力时会明确给出警告。

## 5. 流程与入口

1. 参与共创页：`/intake`（导航「参与共创」）；接口：`POST /api/v1/agent/landmarks/intake`。
2. 我的贡献记录：`/contributions`，只显示当前登录用户自己的条目，包含状态（待审核 / 已核验待发布 / 已发布 / 已拒绝 / 已下架删除）、最近一次审核意见与更新时间；接口 `GET /api/v1/me/contributions`。
3. 字段契约、必填项与审核标准见 `docs/数据采集规范.md` 与 `docs/来源分级与审核准则.md`。
4. 配置前提：`DEEPSEEK_API_KEY`（或任意 OpenAI 兼容 LLM Key）用于 AI 找图与智能解析，可在「个人密钥」页 `/account/api-keys` 填写自己的密钥；联网核实与 LLM 共用同一 Key（`/v1/tools/search`）。`AMAP_WEB_SERVICE_API_KEY` 可选，缺失时会跳过坐标补全并给出警告。未配置密钥不影响基础目录浏览与基础行程规划。

## 6. 去重与修改

相同「作品 + 地标名 + 地址」的组合会被去重拦截（HTTP 409），不会产生重复条目。已有条目可由管理员或该条目的提交者编辑（详情页仅在具备权限时显示「编辑内容与相册」入口）。

提交者的修改（文字或相册）会让**该条地标**回到「待审核」并暂时下架，重新通过审核并发布后才会再次公开；同一作品下的其他已发布地标不受影响。保存成功不等于立即公开，页面会明确提示这一点。相册提交带版本校验：若相册已被其他窗口更新，提交会返回 409 并要求刷新后比较差异。
