# 共创贡献规范

## 1. 提交方式

共创采用 **Harness PR 工作流**：一条地标 = 一个 CSV 文件 + PR 审核机器人。共创者使用主流 AI 智能体工具（Codex、Claude Code、WorkBuddy、Qoder 等）按提示词包自动联网核实、生成条目文件并提交 Pull Request；GitHub 审核机器人自动校验条目字段、三段式简介与重复性，通过后由维护者人工确认合入。候选内容不会出现在公开目录、导出或地图中。

## 2. 署名与身份

每次 PR 合入都会由发布流水线以 PR 作者的 GitHub 用户名写入 `landmark_contributions` 署名记录：

1. `contributor_name`：PR 作者的 GitHub 用户名，审核发布后显示在地标详情页。
2. `landmark_id`：指向本次合入的候选地标，因此可准确追踪“谁提交了哪一条”。

署名无需在条目文件中填写，合并导入时自动确定。

## 3. 审核与公开

PR 条目经机器人确定性校验与维护者人工合入后，随既有 `seed_initial_landmarks` 发布流程进入候选 → 审核 → 发布链路；只有变为 `verified` 并发布后才对公众可见，详情页显示共创者的 GitHub 用户名。

## 4. 数据边界

不要填写联系方式、住址、证件信息或其他不必要个人信息。公开署名为你的 GitHub 用户名。每条简介必须使用“在作品中的重要地位”“主要出现的情节”“现实地标介绍”三段式原创内容，并提供可访问来源链接。

## 5. 流程与入口

1. 完整流程、工具启动方式与常见问题见 `docs/共创提示词包/00_使用说明.md`。
2. 可直接整段复制的提示词见 `docs/共创提示词包/01_共创条目添加提示词.md`。
3. 条目文件格式与校验规则见 `data/contributions/entries/README.md` 与 `scripts/validate_contribution_entry.py`。

## 6. 共创者名单页面

项目前端提供 `/contributors` 独立页面（及 `GET /api/v1/contributors` 接口），实时读取 `data/contributions/contributors.json`，展示共创者的 GitHub 用户名、GitHub 主页、加入时间与累计合并条目数。名单文件仅由发布流水线维护，共创 PR 不得修改。

## 7. 与既有审核流程的关系

PR 条目经机器人确定性校验与维护者人工合入后，随既有 `seed_initial_landmarks` 发布流程进入候选 → 审核 → 发布链路；机器人只备数据，不直连生产数据库。
