# 02 — 共创提示词包与本地护栏

## 1. 摘要

- 优先级：P0（用户核心诉求 1）
- 预计工作量：2–3 人日
- 直接依赖：01（提示词引用 01 的目录契约与校验脚本）
- 阶段目标：交付共创者「复制即用」、工具无关的提示词包，兼容 Codex、Claude Code、WorkBuddy、Qoder 等主流 AI 智能体；同时提供本地文件护栏脚本，与提示词约束形成双保险，确保共创者只改动条目文件。

## 2. 前置阅读

1. 01 阶段的 `data/contributions/entries/README.md` 与 `scripts/validate_contribution_entry.py`。
2. `docs/共创贡献规范.md`、`docs/数据采集规范.md`、`docs/来源分级与审核准则.md`。
3. `README.md`（用于撰写使用说明中的环境准备）。

## 3. 任务详情

### 3.1 提示词包目录 `docs/共创提示词包/`

1. `00_使用说明.md`：共创者准备步骤（注册 GitHub、fork 仓库、克隆、创建 `.venv` 并安装依赖）、Codex / Claude Code / WorkBuddy / Qoder 四种工具的启动与粘贴提示词方式、完整使用流程、常见问题（校验失败怎么办、机器人留言怎么读、PR 被要求修改后如何更新）。提示词包正文保持工具无关，各工具差异只写在本文件。
2. `01_共创条目添加提示词.md`：可整段复制粘贴到任一 Harness 的主提示词，固定包含以下章节：
   1. 角色与目标：资深 IP 地标编辑，按项目规范新增 1 条共创地标条目。
   2. 必读文件清单：`data/templates/landmark_candidate_template.csv`、`docs/数据采集规范.md`、`docs/来源分级与审核准则.md`、`data/contributions/entries/README.md`、`scripts/validate_contribution_entry.py` 用法。
   3. 信息收集：先确认「作品名、地标名」，并向用户追问作品与地标关联、可选来源链接；信息不足时提问，不得编造。署名不需要填写，合并时自动使用共创者的 GitHub 用户名。
   4. 硬性约束（不可协商）：只允许在 `data/contributions/entries/<ip_type>/` 下新建 1 个 CSV 文件；严禁修改 `app/`、`tests/`、`alembic/`、`scripts/`、`data/seed/`、`data/contributions/contributors.json`、`.github/`、`docs/`、`requirements.txt`、`README.md` 等任何其他文件；严禁执行 `git push` 之外的仓库级命令（不迁移数据库、不改配置）。
   5. 执行步骤：读规范 → 联网核实作品关联与官方来源 → 撰写三段式原创简介 → 按模板生成单行 CSV → 运行校验脚本直到 valid → 运行本地护栏脚本 → 创建分支、提交（仅含 1 个新文件）、推送、开 PR（按固定标题/描述模板填写作品与地标信息）。
   6. 禁止事项：不编造来源与地址、不复制版权内容、不填未经核实的交通/营业信息、坐标缺失留空、不修改或删除他人条目与任何既有文件。
   7. 完成定义（DoD）：校验 valid、护栏通过、PR 仅含 1 个新增 entry 文件、PR 描述完整。
3. 首期不单独提供「修改/撤回」提示词；在 `00_使用说明.md` 中说明：修改已合并条目同样走新 PR，且只改自己名下条目文件，不得覆盖他人文件。

### 3.2 本地护栏脚本 `scripts/guard_contribution_files.py`

1. 输入：`git diff --name-only` 结果或 `--changed-files` 参数。
2. 逻辑：允许集 = `data/contributions/entries/**`；任何其他路径 → 输出违规清单并以非零码退出。
3. 用途：Harness 提交前自检；同时提供 `.githooks/pre-push` 示例（配合 `git config core.hooksPath .githooks`），供有经验的共创者启用。机器人（03）是最终权威，本地护栏只是提前拦截体验优化。

### 3.3 文档同步

在 `docs/共创贡献规范.md` 增加「PR 共创方式」一节，说明两种提交路径（网页 `/contribute` 与 Harness PR 工作流）的适用场景、署名规则（GitHub 用户名）与共创者名单页面 `/contributors`，并指向提示词包。

## 5. 示例：主提示词骨架（节选）

```text
你是 Worldmark 项目的资深 IP 地标编辑。任务：为共创者新增 1 条 IP 地标共创条目。
硬性约束：只能新建 data/contributions/entries/<ip_type>/ 下的 1 个 CSV 文件；
不得修改 app/、tests/、alembic/、scripts/、data/seed/、data/contributions/contributors.json、
.github/、docs/ 及仓库根目录任何其他文件。
执行前先阅读 data/templates/landmark_candidate_template.csv 与 docs/数据采集规范.md；
生成条目后必须运行 scripts/validate_contribution_entry.py 直到 valid，再运行 scripts/guard_contribution_files.py；
最后创建分支、提交唯一新文件、推送并打开 PR。任何信息不足时先向用户提问，不得编造来源或简介。
署名自动使用你的 GitHub 用户名，无需写入文件。
```

## 6. 禁止修改与风险红线

1. 提示词不得引导共创者执行除 `git push` 之外的仓库级操作（如数据库迁移、改配置、跑测试套件以外命令）。
2. 提示词不得要求模型绕过校验脚本（例如手工构造数据跳过校验）。
3. 护栏脚本只读 diff，不做任何删除、移动或写入操作。
4. 不把任何 API Key 或密钥写进提示词包；提示词包内容入库前人工通读一遍。

## 7. 验收标准

- [ ] 按 `00_使用说明.md` 从零走通：克隆 fork → 粘贴 `01_共创条目添加提示词.md` → AI 智能体自动生成合法 entry 文件 → 校验 valid → 提交推送开 PR，全程无需人工写代码。
- [ ] 提示词包在 Codex、Claude Code、WorkBuddy、Qoder 中至少实测两种（其余给出使用说明即可）。
- [ ] 故意让 AI 智能体尝试修改 `app/` 下文件时，提示词约束与护栏脚本都能阻止该行为。
- [ ] `tests/scripts/test_guard_contribution_files.py` 全绿。
