# 共创提示词包 · 使用说明

> 适用对象：希望通过 AI 智能体（Harness）为 Worldmark 项目新增 IP 地标条目的共创者。
> 你需要会使用 GitHub 的基本操作（注册、克隆、推送、开 PR）。其余由提示词驱动的 AI 智能体自动完成。

## 1. 两种参与路径

1. **网页提交（`/contribute`）**：无需代码，适合单条提交；署名手动填写，候选条目进入人工审核。
2. **Harness PR 共创（本提示词包）**：适合希望批量、可复用、可追溯的共创者；条目以独立 CSV 文件提交 PR，由 GitHub 审核机器人自动校验，维护者合入后自动归档并记入共创者名单。

本提示词包只描述第 2 条路径。

## 2. 环境准备

### 2.1 注册 GitHub

注册一个 GitHub 账号并登录。后续署名使用你的 GitHub 用户名，请勿使用临时或无法接收通知的账号。

### 2.2 获取仓库访问权

1. **仓库为公开时**：打开仓库主页，点击右上角 **Fork**，得到你自己的副本（`<你的用户名>/Worldmark`）。
2. **仓库为私有（内部测试阶段）时**：不能 fork。请向维护者提供你的 GitHub 用户名，由维护者把你添加为仓库协作者后，直接在仓库内新建分支开 PR。

### 2.3 克隆仓库并准备环境

把仓库克隆到本地（把下面的地址换成你的仓库地址）：

```powershell
git clone https://github.com/<你的用户名>/Worldmark.git
cd Worldmark
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

> 本项目只使用项目内的 `.venv` 虚拟环境，不要使用系统 Python 安装依赖。

## 3. 使用流程（核心三步）

1. **复制提示词**：打开 `docs/共创提示词包/01_共创条目添加提示词.md`，整段复制。
2. **粘贴到你的 Harness**：按下面第 4 节启动对应工具，把提示词粘贴进去，然后回答 AI 智能体关于「作品名、地标名、作品与地标的关联、可选来源链接」的追问。AI 会联网核实、生成条目文件、运行校验与护栏脚本，最后创建分支、提交、推送并开出 PR。
3. **等待机器人评审**：PR 开出后，GitHub 审核机器人会自动留言；全部通过后等待维护者合入，合入后你的用户名会进入共创者名单（`/contributors` 页面）。

## 4. 各工具启动与粘贴方式

提示词正文与工具无关；以下只是各工具的打开方式和粘贴位置。

### 4.1 Codex（推荐）

1. 安装并打开 Codex 桌面应用或 CLI。
2. 在任务输入框粘贴 `01_共创条目添加提示词.md` 全文，回车开始。
3. 确认任务开始时提示的工作目录是项目根目录（包含 `data/`、`scripts/`、`app/` 的目录）。

### 4.2 Claude Code

1. 在项目根目录打开终端，运行 `claude`。
2. 在对话输入框粘贴提示词全文，回车开始。
3. 首次运行如需授权文件写入，请选择「仅允许项目内路径」并注意只放行条目相关文件。

### 4.3 WorkBuddy

1. 打开 WorkBuddy，新建一个任务并选择/打开本项目目录。
2. 把提示词全文粘贴到任务描述中，开始执行。

### 4.4 Qoder

1. 打开 Qoder，新建对话并选择项目目录。
2. 把提示词全文粘贴到输入框，开始执行。

## 5. 常见问题

### 5.1 校验失败怎么办

机器人留言会列出具体错误（如缺字段、缺三段式前缀、与既有数据重复）。按错误修改本地条目文件后，重新运行：

```powershell
.\.venv\Scripts\python.exe scripts\validate_contribution_entry.py --file data\contributions\entries\<ip_type>\<work-slug>--<landmark-slug>.csv
```

直到输出 `[OK]` 且退出码为 0，再提交推送更新 PR。

### 5.2 机器人留言怎么读

机器人留言是一张表格式评审结果：

- `越界文件检查`：是否只新增了条目文件。
- `条目校验`：每个条目文件的字段、三段式、重复检查结果。
- `来源可达性`：仅提醒，不阻塞。
- 留言最后会给出下一步指引。

### 5.3 PR 被要求修改后如何更新

继续在同一个分支修改，提交并推送即可；机器人会在 PR 更新时自动复查并覆盖留言。不要重新开 PR。

### 5.4 如何修改已合并的条目

首期不提供「修改/撤回」提示词。修改已合并条目同样走新 PR：新建一个条目文件提交，只改动你自己名下对应的条目文件，不得覆盖或删除他人的文件；由维护者审核后处理。

### 5.5 提示词把其他文件改坏了怎么办

本地护栏脚本会在提交前拦截：

```powershell
.\.venv\Scripts\python.exe scripts\guard_contribution_files.py --git
```

若输出 `越界`，说明有非条目文件被改动。请用 `git status` 查看被改动的文件，恢复除条目文件外的所有变更（例如 `git restore <路径>`），再重新执行校验与提交。护栏只是提前拦截；GitHub 审核机器人是最终权威，即使本地漏检，越界 PR 也无法合入。

## 6. 合规提示

- 只录入原创三段式简介和可核验的地点信息；不复制作品正文、台词、剧照或来源页面大段文字。
- 不编造来源 URL 与地址；`transit_text`（交通信息）无可靠来源时必须留空。
- 坐标缺失时留空，不要随意填写。
- 不要修改、删除他人条目或任何既有文件。
