# 数据采集规范

## 1. 适用范围

本规范用于文学、游戏、影视 IP 地标的候选发现、人工录入、审核、发布，以及免费层级预置信息表的内容整理。网络数据发现只允许通过百度智能云“百度搜索” API；禁止应用自动抓取、下载或解析搜索结果指向的网页。该接口直接返回搜索引用，不接入 LLM 模型。

文学、游戏和影视剧分别使用独立门类页面。门类信息由页面入口和标题表达，不在免费层级预置信息表中重复设置“作品类型”表头。

## 2. 搜索调用

1. 使用预定义查询模板，例如 `"{作品名}" 取景地 官方`、`"{作品名}" {城市} 文旅`、`"{地标名}" 地址 官方`。
2. 适配器固定使用网页搜索、`baidu_search_v2`、网页资源类型与安全搜索；不传 `model`、`search_mode` 或深度搜索参数。
3. 每次调用记录查询模板、实际查询、服务商请求标识、引用标题/URL/摘要、时间、调用状态和额度单位。
4. 搜索返回的引用标题、链接与摘要仅用作候选线索；不得直接复制为地标简介或审核结论。

## 3. 免费层级预置信息表

### 3.1 表头

免费层级预置信息表只展示用户浏览和识别 IP 地标所需的概览信息，统一使用以下表头和顺序：

| 作品名称 | 地标名称 | 国家/地区 | 详细地址 | 地标简介 | 信息更新时间 |
| --- | --- | --- | --- | --- | --- |

1. 不设置“作品类型”表头；当前独立门类页面已经表达文学、游戏或影视剧分类。
2. 不设置“来源”表头；来源资料仅用于后台审核和发布把关，不占用免费信息表的展示空间。
3. 使用“详细地址”表头，明确表示地标在现实世界中的地址，避免与文学段落、游戏文本或影视剧情混淆。
4. 不单独设置“省/州”和“城市”表头；相关行政区划统一写入“详细地址”，减少重复信息和横向列数。
5. 不设置“交通参考”表头；交通与到达方式属于地图、路线和个性化行程等后续服务层级。
6. 地标简介必须使用原创文字，并按“在作品中的重要地位”“主要出现的情节”“现实地标介绍”三个部分依次撰写；每部分单独成句，不复制作品正文、剧集台词或来源页面的大段文字。

### 3.2 排版要求

1. 表头名称保持简短，不在表头中添加解释性括号、内部字段名或审核术语。
2. 作品名称、地标名称和国家/地区使用短文本；详细地址与地标简介允许换行，但默认保持为便于快速浏览的长度。
3. 同一门类页面内使用一致的列顺序、对齐方式和日期格式；信息更新时间统一显示为 `YYYY-MM-DD`。
4. 详细地址按“省/州 + 城市 + 区/县 + 街道门牌（或景区入口）”的自然顺序填写，不在单元格内重复国家/地区名称。
5. 免费导出的 CSV 和 XLSX 应与页面表格保持相同字段、名称和顺序。

## 4. 后台 CSV 录入

使用 `data/templates/landmark_candidate_template.csv` 的 UTF-8 编码表头。必填字段：`ip_type`、`work_title`、`landmark_name`、`country_code`、`country_name`、`normalized_address`、`description`、`source_url`、`source_type`、`accessed_at`。

`ip_type` 只能为 `literature`、`game`、`screen`，仅用于把记录归入对应门类；`country_code` 使用 ISO 3166-1 alpha-2；`source_url` 必须是 HTTP/HTTPS URL；`accessed_at` 使用 ISO 8601 时间，例如 `2026-08-10T10:30:00+08:00`。`transit_text` 是可选后台字段：没有可靠来源时必须留空，免费层级预置信息表、公开详情页和免费导出均不展示。完整地址和来源等后台导入字段不等同于免费层级预置信息表的公开表头，可供地图、路线、个性化行程和内容审核使用。

## 5. 发布规则

导入的记录默认是 `candidate`，不能公开。审核人必须给出 `verified` 或 `rejected` 决定和理由。只有 `verified`、拥有至少一个来源且地理字段完整的地标才可发布。

## 6. 内容限制

不录入小说正文、剧集片段、游戏素材、海报或未经许可的图片。地标简介应使用原创三段式摘要；如确有可靠来源，后台交通文字必须标明信息更新时间和来源，且不承诺实时导航、营业状态或安全情况。

## 7. 地标相册共创

相册图片和清单存放于 `data/contributions/landmark_albums/`，页面只通过本地静态链接展示。每张图片必须在 `manifest.json` 中登记替代文字、作者或机构、许可说明；仅接受原创、公共领域或明确可再分发许可的实景图片，不接受作品剧照、游戏截图、海报及授权状态不明的网络图片。

## 8. 条目共创与署名

共创者通过 `/contribute` 提交条目，必须填写公开署名、作品和地标信息、详细地址、三段式地标简介及至少一个来源链接。系统记录署名与候选条目的绑定关系；登录提交还会绑定用户 ID，供后续授权管理使用。候选条目必须完成既有审核和发布流程后才可公开，详见 `docs/共创贡献规范.md`。
